# 4-1 인바운드 경로 제어 (AS-Path Prepend)

## 개요

BGP는 같은 목적지에 대해 여러 경로를 광고받으면, 정해진 순서의 속성 비교를 통해 **best path** 하나를 선정한다.

이웃에게 아무 정책 없이 광고를 보내면 상대는 기본 규칙으로 경로를 고르므로, 나에게 들어오는 트래픽이 **의도한 경로로 오지 않을 수 있다.**

이를 해결하기 위해 이웃에게 광고를 보낼 때(**out**) route-map으로 **AS-Path Prepend**를 설정하여, 상대가 **내가 원하는 경로를 선택하도록 유도**한다. 이때 **AS-Path Prepend**를 설정하여 광고하는 네트워크의 AS-Path를 길게 설정하여 상대 AS에서 들어오는 트래픽을 원하는 경로로 들어오게 할 수 있다.


## 동작 방식

1. 내가 이웃에게 광고를 보낼 때(**out**) route-map으로 AS-Path Prepend를 설정한다.
2. 상대는 여러 경로 중 AS-Path가 더 짧은 경로를 **best path**로 선택한다.
3. 그 결과 나에게 들어오는 트래픽이 **내가 원하는 경로**로 유도된다.

<br>

## 1. 테스트 구성도
<img width="1246" height="671" alt="image" src="https://github.com/user-attachments/assets/0aa701a9-b206-490b-b1cd-94f3f65de273" />

- `AS65001` R1, R2 : AS65001에 속한 라우터로 R3과 ISP가 통신하기 위한 중간 경로이다 **R3**의 20.20.20.1/32을 광고한다.
- R3 : ISP와 통신하기 위한 라우터로 20.20.20.1/32의 호스트 IP를 가지며 R1, R2 방향으로 static 라우팅을 잡고 있다. (우선순위는 R1 방향)
- `AS65002` ISP : R3과 통신하기 위한 라우터로 `AS65002`이며 **R1**과 **R2**와 `eBGP` 피어링을 맺고 있다.

<br>

## 2. 테스트 시나리오

1. MED로 `AS65001`를 주 회선으로 정하고, **ISP**가 **R1** 방향을 **best path**로 선택하는지 확인한다.
2. AS가 광고하는 네트워크 2개(20.1.0.0/30, 30.1.0.0/30)가 서로 다른 회선을 **best path**로 잡도록 prefix별 MED를 설정한다.

<br>

## 3. 테스트


### R1 Config (AS65001)
```java
ip route 20.20.20.1/32 10.0.100.2

route-map MAP_MED_100 permit 10
  set metric 100 
vrf context management

interface Ethernet1/1
  no switchport
  ip address 10.0.100.1/30
  no shutdown

interface Ethernet1/2
  no switchport
  ip address 10.0.10.1/30
  no shutdown

router bgp 65001
  router-id 10.255.0.1
  address-family ipv4 unicast
    network 20.20.20.1/32
  neighbor 10.0.10.2
    remote-as 65002
    address-family ipv4 unicast
      route-map MAP_MED_100 out
```

---

### R2 Config (AS65001)
```java
ip route 20.20.20.1/32 10.0.200.2

route-map MAP_MED_200 permit 10
  set metric 200 
vrf context management


interface Ethernet1/1
  no switchport
  ip address 10.0.200.1/30
  no shutdown

interface Ethernet1/2
  no switchport
  ip address 10.0.20.1/30
  no shutdown

router bgp 65001
  router-id 10.255.0.2
  address-family ipv4 unicast
    network 20.20.20.1/32
  neighbor 10.0.20.2
    remote-as 65002
    address-family ipv4 unicast
      route-map MAP_MED_200 out
```

---

### R3 Config 
```java
interface Ethernet1
   no switchport
   ip address 10.0.100.2/30
!
interface Ethernet2
   no switchport
   ip address 10.0.200.2/30

interface Loopback0
   ip address 20.20.20.1/32

ip route 0.0.0.0/0 10.0.100.1
ip route 0.0.0.0/0 10.0.200.1 10
```

---

### ISP Config (AS65002)
```java
interface Ethernet1
   no switchport
   ip address 10.0.10.2/30
!
interface Ethernet2
   no switchport
   ip address 10.0.20.2/30
!
router bgp 65002
   router-id 10.255.0.3
   neighbor 10.0.10.1 remote-as 65001
   neighbor 10.0.20.1 remote-as 65001
```
---

`AS65001`인 **R1**과 **R2**에서 **ISP**에게 20.20.20.1/32을 광고할 때 MED를 각각 **50**과 **100**으로 설정하여best path를 **50**의 값을 가지는 **R1**이 best path로 선정될 수 있도록 하였다.

---
### best path 확인
```java
ISP(config)#show  ip bgp 20.20.20.1
BGP routing table information for VRF default
Router identifier 10.255.0.3, local AS number 65002
BGP routing table entry for 20.20.20.1/32
 Paths: 2 available
  65001
    10.0.10.1 from 10.0.10.1 (10.255.0.1)
      Origin IGP, metric 100, localpref 100, IGP metric 1, weight 0, received 19:37:54 ago, valid, external, best
      Rx SAFI: Unicast
  65001
    10.0.20.1 from 10.0.20.1 (10.255.0.2)
      Origin IGP, metric 200, localpref 100, IGP metric 1, weight 0, received 19:37:52 ago, valid, external
      Rx SAFI: Unicast
```
`ISP`에서 20.20.20.1/32의 `best path`는 10.0.10.1로 선정되었다. 두 경로는 `weight(0)`, `localpref(100)`, `AS-PATH(65001)`, `Origin(IGP)`이 모두 동일하고 같은 `AS65001`에서 수신되었으므로 MED 비교 조건이 충족된다. 따라서 Metric이 더 낮은 100인 10.0.10.1 경로가 best path로 선정되었다.
